# Era-specific pixel court art design

## Goal

Replace the procedural Jack, Queen, and King illustrations with deliberately authored pixel art that reads as the same mirrored court characters in every display era. Each era receives art created for its own native pixel grid, rather than an antialiased master image scaled down for lower-resolution modes. At the same time, remove the unintended green depth-outline rectangles around cards from the normal presentation.

## Scope

- Add one King, Queen, and Jack character sprite for each display profile: 1980s, 1990s, and early 2000s.
- Keep each character's identity, pose, costume design, and two-way mirrored composition consistent across the three eras.
- Increase palette range and detail with the era resolution while retaining a visibly pixel-authored style at every level.
- Keep rank labels and suit glyphs code-rendered so each character sprite can be reused for all four suits.
- Disable the global green depth-outline pass by default. Retain `Alt+O` as an explicit developer/debug toggle for that pass.

## Artwork design

The generated source is a transparent 3-by-3 court-card atlas. Columns contain King, Queen, and Jack; rows contain the 1980s, 1990s, and early-2000s treatments. The atlas must show the same characters and costumes in all three rows, with only the available pixel density, palette sophistication, and small ornamental detail changing.

Every court figure uses the traditional two-way mirrored playing-card composition. The artwork contains no rank letters, suit symbols, card border, paper background, shadows outside the figure, captions, or typography. Those elements remain controlled by the renderer and therefore stay geometrically identical across suits and eras.

The intended era treatments are:

- **1980s:** chunky arcade pixel clusters, a tightly limited high-contrast palette, simplified faces and costume ornaments, and strongly readable silhouettes.
- **1990s:** finer pixel clusters, a broader but still disciplined palette, clearer faces, and additional costume shading and ornament.
- **Early 2000s:** the richest palette and detail, with refined pixel-level shading and ornament, but still hard-edged pixel art rather than smooth illustration.

The built-in image-generation workflow produces the atlas. If one generation cannot maintain character consistency and exact grid separation, follow-up image-edit iterations may correct the same atlas or individual cells. The generated atlas is a source artifact, not a runtime-scaled substitute for the native sprites.

## Native asset contract

Each final cell is extracted and deliberately pixel-finished at the exact runtime size for its profile:

| Profile | Native sprite size | Palette treatment |
| --- | ---: | --- |
| `eighties` | 30 x 56 px | strict limited palette |
| `nineties` | 60 x 112 px | expanded quantized palette |
| `early2000s` | 120 x 224 px | high-detail quantized palette |

Final assets live at:

```text
assets/cards/courts/source/court-atlas.png
assets/cards/courts/eighties/K.png
assets/cards/courts/eighties/Q.png
assets/cards/courts/eighties/J.png
assets/cards/courts/nineties/K.png
assets/cards/courts/nineties/Q.png
assets/cards/courts/nineties/J.png
assets/cards/courts/early2000s/K.png
assets/cards/courts/early2000s/Q.png
assets/cards/courts/early2000s/J.png
```

The source atlas is retained for provenance and future controlled edits. Runtime code loads only the extracted native sprites.

## No-antialiasing invariants

The following rules are mandatory throughout generation, extraction, loading, and rendering:

1. Final sprite alpha is binary: every pixel is either fully transparent or fully opaque.
2. Final colors are palette-quantized per era; no semitransparent edge pixels or smoothing gradients are permitted.
3. Each profile loads its own exact-size sprite. No era asset is generated by runtime scaling of another era's asset.
4. Canvas `imageSmoothingEnabled` is `false` before every court-sprite draw.
5. GPU texture minification and magnification use nearest-neighbour filtering for pixel court assets.
6. Any offline extraction or cleanup uses nearest-neighbour resampling only. Where generated source detail does not map cleanly, pixels are manually or deterministically quantized at the target grid instead of antialiased downsampling.
7. Tests guard the smoothing and native-size selection rules so a future rendering refactor cannot silently reintroduce antialiasing.

The higher-resolution variants may contain genuinely improved art, but they are separately authored native rasters—not smoother resamples of the 1980s sprite.

## Loading architecture

A court-art asset module owns the profile/rank manifest, decoded-image cache, and preload operation. The application preloads all required court sprites before it creates the first rendered cards. This avoids cards changing appearance after the opening frame and keeps the synchronous card-render path simple.

The cache key is the display profile plus rank. The public lookup accepts the renderer's `cardArtLevel` and rank, maps that pair to the correct native asset, and returns the already decoded image. Switching eras selects a different cached native image without modifying game state.

If an image is missing, corrupt, or cannot be decoded, loading records the failure and the renderer uses the current procedural court illustration for that rank. A failed cosmetic asset must not prevent the game from starting or dealing cards. The fallback also uses the existing era-native raster path and never substitutes a higher-resolution sprite by downscaling it.

## Render flow

For a Jack, Queen, or King, the card renderer:

1. Determines the active `cardArtLevel` from the display profile.
2. Looks up the cached sprite for that level and rank.
3. Disables canvas image smoothing and draws the sprite within the existing court-art bounds at a one-to-one native relationship with the profile raster.
4. Draws the existing code-rendered suit symbol treatment over or alongside the figure as required by the current layout.
5. Draws the existing corner rank and suit indices after the central artwork.

Number cards, aces, jokers, card backs, card dimensions, layout coordinates, and gameplay behavior remain on their existing paths.

## Green card-rectangle fix

The green rectangles are the default-enabled global depth-outline debug effect, not part of the card artwork. Normal startup sets the outline pass to disabled in both renderer construction and scene initialization. Its green color and tuning can remain available for diagnostics, and `Alt+O` continues to toggle it deliberately.

Disabling this effect does not remove the intended thin neutral card border drawn by the card renderer. Profile changes, compositor rebuilds, and context restoration must preserve the normal default-off state unless the developer explicitly enabled the debug toggle during that session.

## Verification

Automated checks cover:

- the manifest maps all nine profile/rank combinations to distinct native files;
- decoded images report exactly 30 x 56, 60 x 112, or 120 x 224 pixels for their profile;
- all final sprite alpha values are binary and their palette sizes stay within the selected era budgets;
- the card renderer selects by `cardArtLevel`, disables image smoothing before drawing, and does not scale one profile's asset into another profile;
- a load failure uses the procedural fallback without breaking card rendering;
- the outline effect is disabled by default and remains available through the existing debug toggle;
- the early-2000s direct presentation path remains free of CRT processing.

Browser visual QA captures the same J, Q, and K in all three modes. Review confirms consistent character identity and mirrored composition, progressively richer native art, crisp hard pixel edges, no green debug rectangles, no antialiased halos, and no unexpected CRT treatment in early-2000s mode.

## Non-goals

- No changes to game rules, card layout, UI geometry, animation, or sound.
- No new art for number cards, aces, jokers, or card backs in this change.
- No suit-specific court character variants; rank art is shared across suits.
- No changes to the approved CRT presets or to the clean early-2000s presentation path.
- No runtime procedural conversion of vector or high-resolution art into the low-resolution variants.
